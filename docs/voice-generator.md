## Speed and runtime

Phonon's `duration_delta` is a continuous model conditioner fixed at `PhononTTS.load`, not a synthesis-time speed multiplier. The pinned CLI guide says negative values speak faster, positive values slower, and zero is normal; large values make speech less reliable. The runtime accepts finite numeric values and defines no hard numeric range. Both models expose the same Speed slider from 0.5× to 1.5×, in steps of 0.05, centered at 1×. Kokoro receives this value directly; Phonon receives `duration_delta = 1 - speed`, rounded to two decimals, so faster settings become negative adjustments. This keeps Phonon's conditioner within −0.5…0.5; it is a UI guardrail, not a claimed model training range. Phonon's multiplier is a relative control, not a guarantee of an exact duration ratio. Normal-speed previews use `duration_delta: 0`, without per-voice adjustments. Live readouts update while dragging, and switching restores each model's independent speed.

The browser integration requests q8, `device: auto`, and one CPU thread. The official runtime tries usable WebGPU and falls back to the same model on CPU, reporting its device reason. No isolation headers are introduced. SIMD/module-worker load errors remain recoverable; model selection never silently changes. A runtime is disposed after each job, including failed or invalidated jobs. Kokoro runs in a dedicated module worker; each WebGPU/CPU load attempt gets a fresh worker because failed ONNX WebGPU initialization can poison a same-realm CPU retry. Failed attempts terminate before fallback, and worker crashes reject pending requests. Asset pinning stays inside that worker rather than repeatedly wrapping the page's global fetch. The next job reloads from browser cache rather than retaining two models in memory. Switching during loading invalidates the result and blocks new jobs until loading settles; the library does not expose a load abort handle. Switching during Phonon synthesis aborts its stream.

Both models use the shared paragraph/sentence/clause-aware chunker: Phonon has a 40-word target and Kokoro retains its 60-word target. Short edge fragments can be merged into a neighbour, so these are targets rather than strict caps. Phonon's built-in splitter still runs inside each request. Each Phonon passage uses the runtime's default temperature and seed; the client awaits its complete PCM stream before starting the next passage, then encodes the ordered result once. Shorter Phonon requests mitigate the repetition observed with longer inputs, but do not guarantee error-free speech. Both models support timed-pause notation such as `[0.5s]` and `[1s]`. The application splits at each tag, drains the preceding speech request, and inserts the requested silence at the runtime sample rate without sending the tag to the model. Both downloads are encoded locally at the runtime sample rate; neither partial playback nor streamed autoplay is exposed.

## MP3 export recovery

MP3 export is optional after synthesis completes. If the external encoder cannot load or throws, the completed WAV remains available for playback and download. The MP3 button stays visible but disabled, with an encoder-specific warning rather than a model/runtime failure. Generate retries the full job, including MP3 preparation; successful retry clears the warning and restores both downloads. A model switch still invalidates every result from the old job, including a WAV fallback.

```sh
pnpm exec node scripts/check-voice-export.mjs
```

This focused Chrome harness checks encoder-download failure, encoder exceptions and a model switch during the encoder exception for both models. It decodes the surviving WAV, checks control/error/worker state, then restores the encoder and decodes a successful MP3 retry. Use `VOICE_SMOKE_ORIGIN` for a different local server and `VOICE_EXPORT_OUTPUT` for a separate evidence directory. The regression checks first failed on WAV availability for both encoder failures/models, while stale-result cases already passed; all six scenarios passed after the correction. These checks do not establish perceptual quality or Safari-specific encoder-failure behavior.

## Sizes and claims

The pinned Hugging Face tree API reports q8 weights of 64,512,352 bytes (61.5 MiB), tokenizer JSON of 277,967 bytes, and config of 4,634 bytes. The installed single-thread WASM files are each about 4.2 MiB; the browser selects its SIMD variant, not both. Selected voice embeddings and JavaScript add overhead. These are inspected file sizes, **not** a measured total browser download or memory estimate. Browser caches may be evicted or revalidated. Do not use vendor native benchmark numbers as browser performance claims.

The model and voice catalogue carry Apache-2.0 labels. The runtime is MIT OR Apache-2.0 and includes third-party notices. These labels do not grant blanket rights to generated speech; users remain responsible for text and other applicable rights.

```sh
VOICE_PREVIEW_MANIFEST=local/phonon-previews-97-complete/manifest.json \
  pnpm exec node scripts/check-voice-acceptance.mjs
```

The harness uses a fresh Chrome profile with GPU disabled, observes page and worker requests, and writes `/tmp/voice99-remaining/report.json`. It checks rendered selection/preview names, groups and URLs; loads all 65 native preview players; separately downloads and decodes every MP3; and compares all 37 Phonon hashes with the handoff. The public media origin does not grant cross-origin JavaScript reads, so file hashing uses Node fetch rather than changing site headers or bypassing browser security. Native media loading is checked independently.

It also exercises independent settings and validation, live slider readouts, failed previews followed by real synthesis, controlled worker/WebAssembly unavailability and retry, normal/fast/slow generation, timed pauses, decoded MP3/WAV downloads, and actual in-flight switching. Phonon switches after a real PCM frame; Kokoro switches after dispatching a real generation and before its reply. The report includes output durations, status messages, worker lifecycle, asset traffic and Cache API inventory. Worker counts are not a total-memory measurement, and short-fixture timings are not target-device performance claims. Controlled runtime failures are not physical-device compatibility tests. The script's presence is not executed acceptance evidence. Run the unit suite and build before these browser checks: their temporary fixture configuration and dependency-cache changes can reload a running dev page.

## Verification boundary

Focused tests exercise session defaults, independent settings, invalid voice/speed rejection, serialized jobs, stale loads/generation/disposal, cleanup/retry, ordered complete PCM assembly, stream errors and text validation. Catalogue checks assert group counts, unique stable IDs and preview mappings. They use controlled runtime doubles and do not establish real model audio quality.

`scripts/smoke-voice-generator.mjs [phonon|kokoro]` uses the existing Chrome/CDP dependencies against `VOICE_SMOKE_ORIGIN` (default `http://localhost:4321`). It exercises model/state selection, a multi-sentence passage with a long sentence, complete-output gating, WAV decode and download enablement, and request inspection across attached page and worker targets. Run results and environment limitations are reported separately; the script's presence is not a pass. Set `VOICE_SMOKE_GPU=1` to require actual WebGPU execution, not merely expose an adapter. The harness records Phonon's initialized `device`, `deviceReason` and thread count from the official worker reply; Kokoro's successful load reply is associated with its requested backend. CPU runs assert `cpu` for Phonon and `wasm` for Kokoro. A GPU-enabled run that falls back to CPU fails the backend assertion. Successful runs retain WAV/MP3 audio, input text and a screenshot under `/tmp/voice96-audio/` for listening and review; set `VOICE_SMOKE_OUTPUT_DIR` to keep a follow-up run separate from earlier evidence. The default sample includes a single sentence over 300 words as well as shorter sentences. Set `VOICE_SMOKE_ESSAY=when-ai-stops-being-a-tool` to use the complete rendered essay prose, excluding summaries, images and credits. Add `VOICE_SMOKE_LONG_SENTENCE=1` for a 350-word excerpt in original word order with sentence punctuation removed; this is an essay-derived stress fixture, not an edit to the published essay. `VOICE_SMOKE_TIMEOUT_MS` can extend the default ten-minute generation timeout for long inputs. Output filenames include the essay slug and fixture variant so runs do not overwrite each other. The harness pauses newly attached workers until request observation is enabled and rejects attachment failures. It rejects remote POST requests and requests containing the complete test passage; this bounded trace is not a universal privacy proof. Review the worker sources as well. Safari/iPhone, hardware WebGPU, and perceptual listening need explicit evidence; synthetic PCM checks and headless decoding do not replace them.
